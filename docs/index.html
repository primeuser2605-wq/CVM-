The compiler and VM in action

A short walkthrough: building from source, compiling a script, inspecting the bytecode, and running it on the VM — the actual cvm binary, in a terminal.

The pipeline, stage by stage

Each stage is a pure transformation: same input always produces the same output, stages do not share state. The CLI exposes every intermediate form with inspection flags.

01

Lexer lexer.h · lexer.cpp

One-pass scanner. Reads characters left-to-right, emits a stream of typed tokens. Handles 6 keywords, 8 operators, integers, identifiers, line comments.

x = 10;
if (x < 20) {
    print x;
}

02

Parser parser.h · parser.cpp · ast.h

Hand-written recursive descent. Every grammar rule is one method. Operator precedence is baked into the call chain: expression → comparison → term → factor → primary.

grammar
expression  → comparison
comparison  → term ((== | < | >) term)?
term        → factor ((+ | -) factor)*
factor      → primary ((* | /) primary)*
primary     → NUMBER | IDENTIFIER
            | true | false
            | "(" expression ")"
AST for 2 + 3 * 4
Binary(PLUS)
  Number(2)
  Binary(STAR)
    Number(3)
    Number(4)
03

Compiler compiler.h · compiler.cpp

Visitor over the AST. Emits bytecode into a Chunk. Forward jumps use back-patching: write a placeholder operand, finish the body, then overwrite with the real target.

back-patching pattern
size_t emitJump(OpCode op) {
    chunk_.writeOp(op);
    size_t offset = chunk_.code.size();
    chunk_.writeShort(0xFFFF);   // placeholder
    return offset;
}

void patchJump(size_t offset) {
    uint16_t target = chunk_.code.size();
    chunk_.patchShort(offset, target);
}

Virtual Machine vm.h · vm.cpp

Classic fetch-decode-execute over the bytecode. Operand stack for intermediates, flat slot array for variables. About 165 lines, including 17 opcode handlers.

core loop
while (ip < code.size()) {
    OpCode op = code[ip++];
    switch (op) {
        case OpCode::ADD: {
            int b = popInt();   // right pops first
            int a = popInt();
            push(Value{a + b});
            break;
        }
        // ...16 more cases
    }
}

Portable bytecode .cvmb file format

Save compiled programs to a binary file, ship them anywhere, run without the source. Same idea as .class files for the JVM.

compile once
$ cvm script.cvm -o script.cvmb
Wrote bytecode to script.cvmb
   (171 code bytes, 9 constants)
run anywhere
$ cvm --run script.cvmb
24
6
30
...
191102976

Instruction set

17 opcodes, one byte each. Operands (when present) are 2 bytes big-endian: a 16-bit constant index, variable slot, or jump target.

OpcodeOperandStack effect
stack & constants
PUSH_CONSTconstant idx (u16)push constants[idx]
PUSH_TRUE—push true
PUSH_FALSE—push false
POP—discard top
variables
LOADslot (u16)push variables[slot]
STOREslot (u16)pop into variables[slot]
arithmetic
ADD / SUB / MUL / DIV—pop 2 ints, push int
comparisons
EQ / LT / GT—pop 2 ints, push bool
control flow
JMPtarget offset (u16)ip = target
JMP_IF_FALSEtarget offset (u16)pop bool; if false, ip = target
I/O & halt
PRINT—pop and print
HALT—stop execution

.cvmb binary format

All multi-byte integers are big-endian. The four magic bytes let the loader reject bad files immediately, the same trick PNG, ZIP, and class files use.

0..3 magic 'C' 'V' 'M' 'B'
4 version 1
5..8 constant count uint32
×N constant tag (0=int, 1=bool) + value 1 + (4 or 1) bytes
… code length uint32
… code raw bytecode stream
